## 代码证据（关键）

`FAST_LIO/IMU_Processing.hpp` 的 `IMU_init`：
```cpp
mean_gyr += (cur_gyr - mean_gyr) / N;
...
init_state.bg = mean_gyr;
init_state.grav = S2(- mean_acc / mean_acc.norm() * G_m_s2);
kf_state.change_x(init_state);
```
后续 `UndistortPcl` 使用：
```cpp
angvel_last = angvel_avr - imu_state.bg;
```
因此代码本身**确实存在**“运动初始化时把窗口内真实平均角速度当成 gyro bias”的机制；而且重力方向使用运动期间平均加速度，同样存在动态激励污染风险。由于不知道精确初始化样本窗，不能把 bg 数值与用户0–0.2s平均值不完全相等解读为矛盾。

## Falcon2 A3-B1 相关证据

- A3-B1日志与47帧里程计时间戳最大偏差仅约4ns，归属已确认。
- F2 0.3s扫描: 252匹配, `eig_min=0.268968`, 0.4s扫描: 256匹配, `eig_min=0.551565`。
- 在0.4987s，F2 首帧对齐的位置误差约 (0.01026,-0.02329,-0.52768)m，姿态误差4.3817deg。1.4992s姿态误差45.8659deg。
- `eig_min` 来自 3x3 `H=Σ nn^T` 匹配法向矩阵；它仅是点到平面平移方向约束代理，不是完整状态信息矩阵，也没有最弱特征方向。

## 结论层级

1. **代码机制已证实**：用初始化期间 gyro 样本均值填充 `bg`。
2. **数据高度支持风险**：初始化窗口无人机有显著非零运动角速度；`bg` 大于1rad/s。
3. **因果仍待消融**：无法单凭这些结果证明该 `bg` 是三机 A3 漂移的唯一根因；动态平均加速度重力初始化、LiDAR/IMU 外参、时间与地图几何同样待核对。
4. **下一步仅离线验证**：检查精准初始化样本窗 `N`/日志中的 `mean_gyr`，比较这些实际输入 gyro 的均值与报告 `bg`；独立计算 `gyro - bg` 与姿态差分角速度的残差（应注意对齐时间与机体坐标）。然后进行只改一个因素的仿真消融，不修改已归档 baseline。
